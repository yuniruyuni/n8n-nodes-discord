# Migration guide: 0.2.x → 0.3.0

Version 0.3.0 trims two nodes whose functionality is provided more directly elsewhere and polishes the UI of the remaining four nodes. The on-the-wire data sent to and received from Discord does not change.

## Removed nodes

### `Discord HTTP Interaction Trigger` — removed

**Why.** Discord delivers `INTERACTION_CREATE` over the Gateway WebSocket as well as the HTTPS Interactions Endpoint. The `Discord Trigger` already covers the Gateway path. Maintaining two parallel triggers for the same payload created drift and confused users about which one to pick.

**How to migrate.**

Replace `Discord HTTP Interaction Trigger` with `Discord Trigger`:

| Old node parameter | New equivalent in `Discord Trigger` |
|---|---|
| `path` (HTTPS slug) | _(remove — Gateway is outbound from n8n)_ |
| n/a | `Event` → `INTERACTION_CREATE` |
| n/a | `Connection Name` → `default` (or anything you want) |

Credential: switch from `Discord Interaction API` to `Discord Bot API`. The Gateway connection needs a bot token; the application public key is no longer used for verifying inbound requests in this path.

Downstream `Discord` node operations that respond to the interaction (`Interaction Response → Create Initial Callback`) work unchanged — they POST to `/interactions/{id}/{token}/callback` which Discord accepts regardless of how the original interaction was delivered. The 3-second response deadline still applies.

**If you need HTTPS-only interaction reception (no bot account)**, use n8n's built-in `Webhook` trigger plus a `Code` node that runs the Ed25519 verification. The verification helpers (`buildEd25519PublicKey`, `verifyDiscordSignature`) live in `nodes/DiscordWebhookEventTrigger/DiscordWebhookEventTrigger.node.ts` — copy them into a Code node.

### `Discord OAuth2` — removed

**Why.** The three operations (`Build Bot Install URL`, `Build Authorize URL`, `Get Token Revocation URL`) were thin wrappers around `URLSearchParams`. Keeping them as a dedicated node added a credential-less compute node to the package for ~30 lines of value.

**How to migrate.**

Replace the node with an n8n `Code` node. Copy-pasteable templates live in [`docs/examples/oauth2-url-builders.md`](../examples/oauth2-url-builders.md). Three snippets cover the three operations exactly. Each takes the same input parameters as the old node and returns `{ url }`.

## Renamed node

### `Discord Gateway Command` → `Discord Gateway Send`

Display label only. The internal n8n identifier (`name: 'discordGatewayCommand'`) is preserved, so existing workflows continue to resolve the node correctly. You may notice the new label in the node picker; no action required.

## Removed credential

None. `Discord Interaction API` remains because `Discord Webhook Event Trigger` still uses it.

## Trigger behavior

### `Discord Trigger` default event

The `Event` selector previously defaulted to `MESSAGE_CREATE`. It now defaults to empty and is `required: true`, so the editor will refuse to save the workflow until you pick an event. This avoids silently requesting the `MESSAGE_CONTENT` privileged intent when the user did not mean to.

Existing workflows that explicitly set `MESSAGE_CREATE` (or any other event) are unaffected. Workflows that relied on the empty/default state must explicitly select an event.

## UI improvements

These do not change behavior, only how the form looks:

- Every snowflake ID field has a `placeholder: 'e.g. 123456789012345678'` example.
- The `Discord` REST node has a notice under the `Authentication` selector explaining Bot Token vs OAuth2 user token use cases.
- `Discord Gateway Send` has a leading notice that the matching `Discord Trigger` must be active in the same n8n process.
- `Connection Name` descriptions on both `Discord Trigger` and `Discord Gateway Send` cross-reference each other.
- Activity Type options on `Discord Gateway Send`'s `Update Presence` use user-facing labels (`Playing`, `Listening To`, `Streaming`, `Custom Status`, `None (Clear Activity)`) and describe what the bot will look like in member lists.

## What did not change

- All 26 REST resources, their operations, their `value` identifiers, and their fields' `name` identifiers.
- Gateway event names and metadata.
- Webhook Event Trigger interface.
- Credential schemas.
- The audit log reason field placement.
- Shared payload builders (embeds, components, attachments, allowed mentions, data URI).
